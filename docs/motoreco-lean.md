# MotoRecoログによるロール補完

実装: `proto/motoreco.py`（読み込みと同期）、`proto/leanfusion.py`（リーン角の融合）、`proto/renderer.py`（`Settings.lean` / `lean_ratio`）

## ログ（"TO Custom v1" CSV）の性質

| 信号 | 更新 | 備考 |
|---|---|---|
| RollRate / YawRate | 10ms | 無効値は −125。同期に使う |
| LeanAngle | 中央値60ms、90%は250ms以内 | 0.71°刻み（7bit相当）。**1秒以上止まる区間が80回あり、合計117秒**。実際の傾きより**約7%小さい** |
| Speed | 1s | |

列に絶対時刻がないため、時刻だけでは同期できない。

## 同期

1. カメラのジャイロを車体のロール軸（取り付け補正 `R_mount` の前方向）へ射影し、動画時刻で 10ms ごとの区間に平均して（等間隔の 100Hz）、3Hzの低域通過をかける
2. ログの RollRate と全区間でFFT相互相関を取り、粗同期する（ずれが何分あっても見つかる）。主ピークと第2ピークの比は3.6
3. 30秒の窓（15秒おき）ごとに、粗同期のずれ ±4 秒を 50ms 刻みで探し、窓のずれを直線に当てはめる（中央値の傾き）。その直線の ±60ms を 10ms → 1ms 刻みで詰め、
   `ログ時刻 = a·動画時刻 + b` を当てはめる

このサンプルの結果: `b = −6.440s`、時計の速度差 +5ppm（25分で約7ms）。窓ごとの相関は0.94〜0.99、ずれのMADは8ms。

**X5 の IMU は 1000Hz ではない**（手元の 2 本で 996.3Hz・995.9Hz。X6 は 999.9Hz）。以前はジャイロを 10 サンプルずつまとめて 100Hz とみなしていたので、
X5 では時間の尺度が 0.4% ずれ、粗同期が 2 秒外れ（13 分の動画）、±0.3 秒しか探さない精密化ではどの窓も見つからなかった。リーン角が ±120° になり、
浮遊標識が景色に対して最大 50° 傾いていた（2026-08-13 の動画）。等間隔に区切り直すと、粗同期のピークの比 2.2 → 3.4、窓の相関 0.99、リーン角の誤差 1.1°、
標識の傾きの食い違い（加速度から求めた重力の向きとの差）は二乗平均 29° → 1.8°（X6 の 0919 は 2.6° のまま。`test/signtilt.test.ts`）。
同期に失敗すると、ログで詰める取り付け姿勢（`refineMountWithLog`）もずれる。この動画では前方が 2.0° 左・3.0° 下へずれ、前方の視点で消失点が画面の中央より右に見えていた
（同期を直した後は、まっすぐな所の道路の消失点がほぼ画面の中央）

## リーン角の融合（RTS平滑化）

- 状態: リーン角とジャイロのバイアス
- 予測: カメラのジャイロのロール成分（3Hz以下）を積分する
- 観測: ログの LeanAngle が**更新された時刻だけ**使う。止まっている区間はジャイロでつなぐ
- 尺度: `dLean/dt = k·ω_roll` で k = 0.928（相関0.989）。ログを 1/k 倍して実際の角度にそろえる
  - 根拠: ログ値のまま水平固定すると、電柱がリーン角の約7%（36.5°で約2.6°、−29.8°で約2.1°）傾いて残る。1/k 倍すると約1°以内になる
  - この差が、以前「リーン37°なのに画面は約45°傾いて見えた」原因の一部。実際のリーンは約39°で、残りは広角の透視による見え方

## ロール補完

```
仮想カメラ = qs · R(前後軸, L − G*L) · [R(前後軸, −(1−ratio)·L)] · R_mount · R_視点
```

- `qs`: ジャイロを平滑化した姿勢。ロール成分は G*L になまる
- `L − G*L`: 平滑化で削れたリーンの動き。ログと融合した L から足し戻す（相補フィルタ）
- `ratio`: 画面に残すリーンの割合（1 = 車体と一緒に傾く、0 = 水平固定）

検証（`proto/validate_tilt.py`、1380〜1420秒）: なまり（傾き − L の1Hz以下）

| 設定 | RMS / 最大 |
|---|---|
| σ0.25 | 0.43° / 1.12° |
| 軸別 P0.6/Y0.3/R0.2 | 0.29° / 0.75° |
| σ0.25 ＋ 補完 | 0.07° / 0.32° |
| 軸別 ＋ 補完 | 0.05° / 0.22° |
| σ1.0 ＋ 補完 | 0.55° / 2.0° |

`ratio=0` で画面の傾き = 0.000·L、`ratio=0.5` で −0.500·L（残差RMS 0.2°）。
