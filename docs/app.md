# MotoRecoMovie（アプリ）

（以前の名前は「Insta360 Reframe」。前の名前のときの履歴・設定・編集内容・設定ファイルはそのまま引き継ぐ）

Insta360 X6 の `.insv` を直接読み込み、バイクのオンボード映像向けにリフレームするデスクトップアプリ。

- ホライズンロックなしのスタビライズ（リーンには追従し、振動だけを取る）
- ローリングシャッター補正
- MotoReco の車両ログを使ったロール補完と「傾きを残す割合」（0% = 水平固定）
- キーフレームで視点（ヨー・ピッチ・画角・傾きの割合）を動かす
- GPU（WebCodecs + WebGL2）でデコード・描画・エンコードする。実測で書き出しは約70fps（1080p、RTX 3070）

## 起動

前提: Node.js 24 以上、ffmpeg が PATH にあること（音声の合成に使う）

```bash
cd app
npm install
npm run build
npm start
```

開発中は `npm run dev`（ホットリロード）を使う。

### exe にする（インストーラー）

```bash
cd app
npm run dist
```

electron-builder（`package.json` の `build`）で、`app/dist/` に次のものを作る。

- `MotoRecoMovie Setup <版>.exe`: インストーラー（約 115MB）。インストール先を選べ、デスクトップとスタートメニューに「MotoRecoMovie」のショートカットを作る。アンインストールは Windows の「アプリ」から
- `win-unpacked/`: インストールせずに使えるフォルダ（約 400MB）。中の `MotoRecoMovie.exe` をそのまま起動できる

アプリに入るのは `out/`（ビルドしたもの。車の検出モデルと onnxruntime の wasm も含む）と `package.json` だけ。React などは
ビルドで 1 つにまとまっているので `node_modules` は入れない。アイコンは `build/icon.png`。
コード署名はしていないので、初めて起動するときに Windows の SmartScreen の警告が出ることがある（「詳細情報」→「実行」）。
音声の合成には、exe でも ffmpeg が PATH にあることが必要。

## 使い方

起動すると「最近開いた動画」（最大 12 件）が並ぶ。カードをクリックすると開き、× で履歴から外す（動画は消えない）。
カードにはサムネイル（閉じたときに表示していた場面）、長さ、フォルダ、撮影日時（ファイル名から）、車両ログ・編集内容の有無が出る。
動画が移動・削除されていると「ファイルが見つかりません」になる。ツールバーの「閉じる」でいつでもこの画面へ戻れる（未保存の編集は保存してから閉じる）。
履歴は Electron のユーザーデータフォルダの `recent.json`（`%APPDATA%\MotoRecoMovie\recent.json`。前の名前のフォルダ `%APPDATA%\insta360-reframe` があれば、初めて起動したときに写して引き継ぐ）に保存される。

1. 「開く…」または `.insv` をウィンドウへドラッグ＆ドロップする。車両ログ（MotoReco）は次の順に探して自動で読み込み、映像と同期する
   - プロジェクトに記録してあるログ → 動画と同じフォルダの CSV（MotoRecoViewer で変換したもの）→ .dat のフォルダから映像に合うもの
   - `.dat` は MotoRecoViewer で変換しなくても直接読める。変換規則は MotoRecoViewer と同じ `.ddf` を指定する（サイドパネルの「車両ログ」→「変換規則（.ddf）」）
   - 「フォルダから探す」は、.dat のフォルダ（その下の年ごとのフォルダも含む）から、ファイル名の時刻と映像のジャイロとの相関で同じ走行のものを選ぶ。
     形式・変換式・選び方は [motoreco-dat.md](motoreco-dat.md)
   - 前方（ヨー 0°）と水平は、カメラの付け方によらず動画のジャイロ・加速度から自動で見つける（`core/mount.ts`）。
     前方 = バイクの進行方向、上 = リーンしていないときの車体の上。リーンしていなければ、前方の景色は水平で進行方向を向く。
     - 上 = 走っている間の加速度の時間平均（バイクはリーン中も合力が車体の上下方向）。止まっている間（出発前・休憩・サイドスタンド）は使わない
     - 前後の軸 = 上に垂直な面で、次の 3 つを合わせる: 倒れる回転の軸（ジャイロの主成分。はっきりしていれば正確）、
       加減速の軸（水平な加速度の主成分。直線でも分かる）、ヨーとの関係（ヨー角速度を傾きで回帰。台の揺れに強い）。
       倒れる回転の軸が、ほかの手がかりと 30° 以上食い違うときは、台の揺れを拾っているとみなして使わない
     - 前と後ろ = バイクが曲がる側へ倒れる関係（前方の軸まわりのリーン角と、上まわりのヨー角速度が逆相関）で決めるので、
       レンズを横・上下・後ろへ向けて付けても前が分かる。曲がりが少なく関係が弱い（相関の大きさが 0.1 未満）ときだけレンズ1 の向きに近い方
     - 走行中にカメラの向きがバイクに対して変わる（台が回る・緩む）ときは、時刻ごとに求める（30 秒ほどの幅でならす）。
       動画を通して 12° 未満しか変わらなければ 1 つの姿勢にする
     - 車両ログを読み込んだら、ログ（車速・リーン角・ロール角速度）で詰める（`refineMountWithLog`）
     - ログの車体のロール角速度と直立走行の加速度から求めた正解と比べたずれ（1 分ごとの平均、`test/mount-log.test.ts`）:
       | 動画 | 1 つの姿勢（以前） | IMU だけ | ログで詰めたもの |
       |---|---|---|---|
       | 1011 知床 2 本目（走行中にカメラが 75° 回った） | 上 10〜47°・前 8〜77° | 上 1.9°・前 3.8° | 上 0.9°・前 2.6° |
       | 1011 知床 3 本目（台が揺れる） | 前 4〜43° | 上 1.1°・前 7.4° | 上 0.9°・前 4.8° |
       | 0906 然別 | 上 2〜15°・前 1〜17° | 上 2.3°・前 4.2° | 上 1.4°・前 1.6° |
       | 0919 宗谷丘陵（固定） | 上 2.3°・前 3.6° | 同じ（1 つの姿勢） | 上 2.3°・前 2.9° |
       正解の側にも 2〜4° のばらつきがある。手元の X6・X5 の動画で、映像を見て前後と水平を確かめたもの
       （トップケースの後ろ・バイクの後ろの棒に付けた動画、台が回っていく動画など）はすべて合った
     - キーフレーム・自動生成の視点・追い越しの判定・標識などは、すべてこの前方を基準にする。キーフレームの向きは前方からの角度なので、
       前方の推定が変わっても、自動生成の視点（前方・側方・後方など）はそのまま正しい方向を向く
2. 映像をドラッグすると向き、ホイールで画角が変わる（30〜180°）
   - 画角 135° までは普通の透視投影。それより広いと 180° にかけて立体射影へ連続的に移り、広角でも画面の端が引き伸ばされない（`render/projection.ts`）。
     立体射影に近いほど、画面の中心から離れた直線は弧に曲がる。以前は 120°〜170° で移していて、画角 140° でトップケースの反射板の線が段差に見えた
     （testdata/seam の `1011-pannier-line`）ので、140° ではほぼ透視投影（k = 0.03）になるようにした
   - 横を向くほど、画面に残すリーンの傾きは弱まり、真横（90°）で水平になる（車体に固定したカメラが横を向いていれば、リーンは画面の傾きではなく上下の動きとして見えるため）。後ろ向きは前向きと逆向きに傾く（後ろを向いた視線は車体の前後軸と逆向きなので、車体に固定したカメラと同じ向き。以前は前向きと同じ向きに傾けていた）
   - キーフレームが1つのときは全体の視点になる
   - 2つ以上あるときは、現在時刻のキーフレームを変更する（無ければ追加される）
3. 右のパネルでスタビライズの強さ（ピッチ・ヨー・ロール別）と、傾きを残す割合を調整する
   - **レンズの継ぎ目の合わせ込み**: 初めて開いたときに、前後のレンズの映像が重なる帯で両方が一致するよう、レンズ1の補正（縁の角度と小さな回転）を裏で推定して保存する（10 秒ほど。終わると通知が出る）。横を向いたときの継ぎ目のずれ（このサンプルで約 2°）が直る。スタビライズ欄でオン・オフと「推定し直す」ができる（[insv-x6-format.md](insv-x6-format.md)）
   - **近い物の継ぎ目も合わせる（動的なつなぎ合わせ）**: 前後のレンズは約 3.3cm 離れているので、欄干・路面・車体など近い物は継ぎ目でずれる。フレームごとに継ぎ目の付近の景色までの距離を求め、その視差を補正する（既定でオン）。「継ぎ目のぼかし幅」（既定 12°）で切り替わりの幅を変えられる
     - 0.3〜0.7m のナンバープレート・トップケースなど、どの距離に合わせても 2 つのレンズの像が重ならない物（物によって距離が違う・片方のレンズにだけ写る物がある）が
       継ぎ目にかかると、幅の広い切り替えでは二重に透けて見える。そういう方位では、つなぎ目の位置を ±8° の範囲で像の差の小さい所（路面など）へずらし、
       切り替えの幅を 1/4（12° → 3°）に狭める。像がよく合う方位はこれまでどおり（`render/seamdepth.ts` の `chooseSeamCut`。詳しくは [insv-x6-format.md](insv-x6-format.md)）
     - 視差の補正は 2 つのレンズを混ぜる帯の中だけにかける（片方のレンズだけが写る所は、そのレンズから見たまま描く）。継ぎ目の近くのトップケースの縁が段違いになるのを防ぐ
     - **自車の継ぎ目を AI で合わせる（試験的、既定オフ）**: トップケース・ナンバープレートなどカメラと一緒に動く物を、動画の 30 秒ごとに作った型（中央値）の上で、
       AI のオプティカルフロー（NeuFlow v2）で 2 つのレンズを合わせ、つなぎ目を決めておく。オンにすると動画を開いたときに裏で作り（GPU で区間ごとに 6〜12 秒）、
       動画の横の `.motorecomovie-body.bin` に保存する。どちらのレンズにも写らない所は AI の補完（LaMa / MI-GAN）で埋める。詳しくは [insv-x6-format.md](insv-x6-format.md)
     - つなぎ目の位置は時間でならした像の差で選ぶ（カメラと一緒に動くケースやプレートの所で、走行中につなぎ目がパラパラ動かないように）。位置を変える所で物を横切らないようにする
     - 模様の無い所では、明るさの違う物（灰色のケースと、片方のレンズにだけ写る黒いカメラの台など）の境につなぎ目を置かない（台の黒い縁がケースに透けて見えるのを防ぐ）
     - 問題が出た場面は `testdata/seam/` に短い .insv に切り出して集めてある（[testdata/seam/README.md](../testdata/seam/README.md)）。つなぎ合わせを直したら、
       `npx tsx tools/seam-cases.ts render` で全部描いて悪くなっていないか確かめる
4. 「画面レイアウト」でテンプレート（全画面・小窓・左右／上下2分割・大1＋小2・上下3分割・4分割）を選ぶ
   - 足りない視点は自動で追加される（2つ目以降は後ろ・左・右向き）。余った視点は非表示になり、キーフレームは残る
   - 分割した画面と小窓には枠線が付く（太さ・色はレイヤーごとに変更できる）
5. 「レイヤー」で画面を細かく組み立てる
   - 「＋ 視点」: 360°映像から別の向きを切り出した画面を追加する（小窓・画面分割）。それぞれが自分のキーフレームを持つ
   - 重ね表示（種類を選んで「＋ 追加」）
     - **サイバー風メーター**：クロノグラフ風と同じ配置・同じ内容（速度なし）で、見た目だけを HUD 風にしたもの。半透明のガラスの文字盤に走査線、区切りのあるネオンの弧（タコ・アクセル・ブレーキ）、発光するリーンの弧と三角の指標、六角形のギア・気温。配色は BMW（M カラー）とネオン
       - エンジン停止中は、メーター全体を灰色にする（線・文字・光の色を、明るさを保った灰色へ）。エンジンが掛かると 0.5 秒かけて元の色に戻る。
         判定は車両ログの回転数（直前 0.5 秒のうち 300rpm を超えていた割合）。車両ログが無い・ログに回転数が無いときは、この演出をせず最初から普通の色
       - ギアと外気温の数字が変わると、縦に流れて入れ替わる（0.3 秒）。数字が増えるとき（シフトアップ・気温が上がる）は前の数字が上へ出て下から新しい数字が入り、
         減るときは逆。新しい数字は入ってくる間に大きくなり（最大 1.4 倍）、置き換わった瞬間から 0.35 秒で元の大きさに戻る。
         書き出しでも同じになるよう、その時刻のテレメトリーから「直前に変わった値と、変わってからの時間」を求めて描く（`render/overlay.ts` の `gearShift`・`airShift`）
       - 外気温は 0.75℃ 刻みで、表示の境目付近では 2 つの値を行ったり来たりするので、表示している整数から 0.8℃ 以上離れたときだけ表示を変える（数字が流れ続けない）
       - 外気温は単位（℃）を付けず数字だけ（六角形に入りきらないため。クロノグラフ風メーターも同じ）。色は温度で変える: 5℃ 以下 水色・30℃ 以上 黄色・35℃ 以上 オレンジ・40℃ 以上 赤・それ以外は白（`render/chrono.ts` の `airTempColor`。エンジン停止中は灰色）
       - 文字はすべて以前の 1.5 倍（`render/cyber.ts` の `TEXT_SCALE`）
     - ギアの信号は変速の途中 0.1〜0.2 秒だけ 0（ニュートラル）を送るので、段と段の間の 0.5 秒未満の 0 は前の段のままにする（「1 → N → 2」とちらつかない。
       止まってニュートラルに入れた長い 0 は N と出る。`core/telemetry.ts` の `holdThroughShift`）
     - **クロノグラフ風メーター**（追加メニューの先頭）。配色は BMW（M カラー: ライトブルー・ダークブルー・レッド。ロゴなどは描かない）と標準：外周の上半分がタコメーター（レッドゾーンつき）、外周の下半分は 6 時から右へアクセル開度・左へブレーキ圧。内側の上半分がリーンメーターで、中央に現在のリーン角と MAX ホールド（車体が反対側へ 3° を超えて切り返すとリセット）。内側の下半分にギア段と外気温。速度は出さない。加速中はタコとアクセル、減速中はブレーキ、コーナリング中はリーンが光る
     - **メーター一式（走行状態で切り替え）**：速度・ギア・回転計・リーンアングル・前後G・外気温をまとめて表示する。走行状態（巡航・加速・減速・コーナリング・停止）に合わせて、配置・大きさ・強調が0.4秒かけて移り変わる。例えば、加速中は回転計とギア、減速中は前後Gとブレーキ、コーナリング中はリーン計、停止中は外気温を強調する
     - **個別のメーター**：速度計・回転計・ギア・リーンアングル・前後G・外気温を1つずつ好きな位置に置ける。対応する走行状態のときに光って強調される
     - **地図**：周辺（進行方向が上・範囲を指定）とルート全体（北が上）の2つの表示。走った区間を明るく、現在地を矢印で示す。形は円か角丸の四角。背景は軌跡の線のみ（地図タイルは未対応）
     - **標高プロファイル**：走行距離に対する標高のグラフと、現在地の標高・勾配（▲上り／▼下り）。全体表示か、現在地を中心にした幅を指定
     - **方位帯**：横にスクロールする方位の目盛りと、現在の方位（例: 143° SE）
     - **数値一覧**
   - 重ね表示を選ぶと、サイドパネルに種類ごとの設定（地図の表示・範囲・形、標高の表示幅、方位帯の幅、回転計の上限・レッドゾーンなど）が出る
   - タイムラインの下端に走行状態の帯を表示する（太さ 14px。色: 巡航 灰・加速 緑・減速 赤・コーナリング 青・停止 黄）
   - タイムラインのグラフは、リーン角（オレンジ、中央が 0°・上下 ±45°）と車速（水色、下端が 0 km/h・左上にその動画の上限）を重ねて描く
   - タイムラインは横方向に拡大縮小できる: ホイールでマウスの位置を中心に拡大縮小、Shift＋ホイール（タッチパッドの横スクロール）で左右に移動。
     グラフの右上の「−」「＋」は再生位置を中心に拡大縮小し、「全体」で全体に戻す。下端のスクロールバーは全体のうち見ている範囲で、
     拡大中はつまみをドラッグして左右に動かせる（つまみの外を押すとそこへ移り、そのままドラッグできる）。再生位置が見ている範囲の外へ出たら追いかける。
     目盛りは見ている長さに合わせて 0.1 秒〜10 分の間隔になる
   - キーフレーム（◆）の色: 自動生成で作ったものはショットの種類で分ける。前方 白・コーナー入口 緑・側方 紫・後方 ピンク・追い越し 黄色
     （[overtake.md](overtake.md)）。手で置いたもの・注目ポイントは青。減速・加速・停止は前方、巡航の左右の景色は側方の色。
     グラフの左上に、そのレイヤーにある種類の凡例が出る。◆にマウスを乗せると、その種類が出る
   - プレビュー上でクリックするとそのレイヤーを選択し、ドラッグ・ホイールはそのレイヤーの視点を変える
   - 選択したレイヤーの枠のハンドルでリサイズ、上部のつまみ（または Shift＋ドラッグ）で移動。画面の端・中央・1/3 の線と、他のレイヤーの辺に吸着する。重ね表示レイヤーは中をドラッグしても移動できる
   - 配置の目印: プレビュー右上の「┼ 十字線」「╳ 対角線」で、画面の中央の縦横の線と四隅を結ぶ線を重ねて出す（G キーでまとめて出し入れ）。プレビューだけの表示で、書き出しには入らない。表示の設定は次回の起動でも残る
   - 位置と大きさは数値（出力に対する %）でも指定できる
   - 標識の見た目は「道路標識風」と「AR 風」から選べる。AR 風は、半透明のホログラム風パネルに「CURVE LEFT / R165 / ▸ 70 m（入口までの残り距離）」を表示し、地面の地点へ光の線を下ろして路面に円形のマーカーを描く。色は半径で変わる（60m 未満 赤・120m 未満 橙・それ以上 青）
   - 視点レイヤーの「コーナーの標識」をオンにすると、これから進入するコーナーの曲線半径を、空中に浮かぶ標識（黄色いひし形のカーブ矢印と「R=165」の補助板）として描く。標識はカーブの外側・路面から 6m の高さに固定され、近づくほど大きくなって通り過ぎる（車両ログが無いときは、動画の動きから推定したコーナーで描く。下の「車両ログが無いとき」）。
     置く位置は「標識の位置」で、コーナーの入口から経路に沿った距離で決める（初期値 −25m = 入口の 25m 手前。プラスにするとコーナーの奥）。
   - 出すのは、これから通る標識のうち、今いる場所から見通せるものだけ（`core/sightline.ts`）。地形のデータは無いので、走る道路の位置と標高で判断する:
     自分から標識への視線が、その間の道路から 10m 以上離れると薄くし、25m 以上で消す（くねくねした峠で、山の向こうの道路の標識が見えてしまうのを防ぐ）。
     視線の下の道路が視線より 2m 以上高いとき（峠の頂上の向こう）も薄くし、6m 以上で消す。見通しのよい平地でも、道路から離れた所を通る視線の標識は出ない
   - 通り過ぎた標識は出さない（標識の地点に着く 0.3 秒前から消していく）。通り過ぎた後に後ろや自車を映す視点でも映らない
     映像を描いたのと同じカメラの向き・同じ投影で描くので、映像に残った細かい揺れにも一緒に動き、景色に貼り付いて見える（[telemetry.md](telemetry.md)）
6. 「画角の自動切り替え」で、選択中の視点レイヤーのキーフレームを自動で作る（書き出し範囲か動画全体）
   - 車両ログが無いときは、動画の動きから推定した走行状態を使う（下の「車両ログが無いとき」）
   - 走行状態に応じたショット: 減速で前方の下へ寄る、加速で前方を少しズームイン、長い巡航で左右の景色を挟む、停止で広角の景色
   - コーナー進入: 通常は ①内側を少し向く（最大リーン×割合）。長いコーナー（初期値 2.5 秒以上）の何本かごと（初期値 2 本）に、②自分を映す（後ろ向き・画角 165°・水平固定で、バイクが倒れて見える）、③真横・内側、④真横・外側（90°・画角 165°・水平固定。コーナーの入口と通過した後を1画面に）を順に挟む。②〜④はそれぞれオン・オフできる
   - 視点の既定値: 切り替える 4 つの視点（前方・コーナー入口 ①・側方 ③④・後方 ②）は、メニューの「設定 → 自動生成の視点…」
     （または「画角の自動切り替え」の「視点の既定値…」）で変える。アプリの設定としてこのパソコンに覚え、次の自動生成から使う
     （今あるキーフレームは変わらない。プロジェクトや設定ファイルには入らない）
     - 前方: ヨー・ピッチ・画角・傾きを残す。減速（下へ寄る・ズーム）・加速（ズーム）・停止の景色・巡航の景色は、これを元に変える
     - コーナー入口: 内側への量（リーン角 × 割合、初期値 60%）と最大の角度（初期値 35°）、ピッチ・画角・傾きを残す
     - 側方: 横への向き（初期値 90°。コーナーの内側・外側へ）、ピッチ・画角・傾きを残す（初期値 165°・水平固定）
     - 後方: ヨー（初期値 180°）・ピッチ・画角・傾きを残す（初期値 165°・水平固定）
     - 画面は右側のパネルに重ねて開き、選んだ視点を、選んでいる視点レイヤーにそのまま映してプレビューする（今のコマ。閉じると元に戻る）。
       コーナー入口と側方は、例としてリーン角 30° の右コーナーで見せる（側方は ③ 内側 / ④ 外側を選べる）
     - 「この視点を既定値に戻す」「すべてアプリの既定値に戻す」で、アプリの既定値（上の初期値）に戻す
     - 以前は、基本の視点を生成する前のレイヤーの視点から取っていた。今は前方の既定値を使う
   - 注目ポイント: プレビュー中に B キーで追加し、向き（左・右・後ろ・空、または角度）と見せる長さを指定する。追い越し以外のどのルールより優先される
   - 追い越し（オプション、既定はオフ）: センターラインをまたいで車を追い越す間、路面が映らないよう上（空と景色、既定は上へ 40°・画角 80°・水平固定）を向く。
     車線をまたぎ始める前に切り替えが終わるよう、切り替え時間の分だけ早く始める。追い越しの場面は動画を調べて見つける（[overtake.md](overtake.md)。
     初回の自動生成のときに 1 分ほどかけて調べ、結果はプロジェクトに残す。「調べ直す」で次の生成のときにもう一度調べる）
     「切り替える車速」（既定 40 km/h）より遅い追い越し（追い越す間の平均の車速）では切り替えない。0 でいつも切り替える。
     車速は車両ログ（無いときは動画の動きからの推定）から求め、分からなければ切り替える
   - 各時刻で優先度のいちばん高いショット（追い越し ＞ 注目ポイント ＞ 減速 ＞ 加速 ＞ コーナー ＞ 停止 ＞ 巡航の景色 ＞ 前方）を選び、指定した時間をかけて振る。最短ショットより短いもの（一瞬だけ前方に戻るものも含む）は捨てる
   - リーン中に横を向いても視線が地面側へ下がらないよう、横を向く回転は水平（重力）を基準にしている。画面の傾きは「傾きを残す割合 × cos(ヨー) × リーン角」（前で +、真横で 0、後ろで −。車両ログがあるとき。`test/view.test.ts` で、傾きを残す 100% が前でも後ろでも車体に固定したカメラと同じ向きに傾くことを確認）
   - 結果は普通のキーフレームなので、そのまま手で直せる。範囲内のキーフレームは置き換わる
7. 「車体挙動の乱れ」をオンにすると、車両ログから挙動が乱れた場面を見つけ、その間だけ自動で 2 画面にして自車を映す
   - 判定に使うもの: スリップ率（急な変化と、空転・ロックのような持続的なずれ。25km/h 以上）、車両の 6 軸センサー（ロール・ヨー角速度と前後・横・上下 G の 1.5〜12Hz の揺れ）、前後サスペンションのストロークの速さ（突き上げ・抜け・底付き）。15km/h 以上の走行中だけ
   - それぞれを「その走行での上位 0.5% の大きさ」（静かな走行で出すぎないよう下限あり）で割った値のいちばん大きいものを乱れの強さとし、しきい値（初期値 1.5 倍）を超えた場面を事象にする（`core/disturb.ts`）
   - 事象の前後に余白（初期値 前 1 秒・後 2.5 秒、最短 4 秒）を付けた間、全画面のメインを半分に縮め、空いた半分に「自車（挙動の乱れ）」の画面を 0.4 秒かけて滑り込ませる。分け方は 左右（前方が左／右）・上下
   - 「自車（挙動の乱れ）」の視点レイヤーは、オンにしたときに自動で作る（後ろ向き・画角 165°・水平固定）。向きや画角はこのレイヤーを選んで変えられる。メインが全画面のときだけ働く
   - 自車の画面の左上に「挙動の乱れ」と、いちばん強かった指標（例: ヨー角速度）を出す（オフにできる）
   - 一覧で事象ごとに 2 画面にするかを選び、時刻へ移動できる。タイムラインには 2 画面にする範囲が赤い帯で出る
   - このサンプルでは、しきい値 1.5 倍で 9 件・2 画面は 8 区間（合計 36 秒 / 25 分）。いちばん強いのは 21:28 の、フロントサスが伸び切った（20mm）直後のヨーの揺れ
8. 設定ファイル（右側の一番上の「設定を保存…」「設定を読み込む…」、`*.motorecomovie-settings.json`。前の名前のときの `*.reframe-settings.json` も読める）: 右側の設定と、画面に置いたメーターなどの位置・大きさを 1 つのファイルにまとめ、ほかの動画でも使える（`engine/settings-file.ts`）
   - 入るもの: スタビライズ・継ぎ目のぼかしなどの設定、すべてのレイヤー（描画順・位置・大きさ・表示・名前・枠線・標識・自車の画面の役割、メーターの種類と設定）、
     視点レイヤーの向き（キーフレームが 1 つのもの）、画角の自動切り替え、車体挙動の乱れ、書き出しのサイズ・コーデック・ビットレート・動画に入る文字の言語
   - 入らないもの（動画ごと）: キーフレームが 2 つ以上ある視点の動き、注目ポイント、追い越しの結果、継ぎ目の合わせ込みの推定値、書き出し範囲、乱れの事象ごとの「2 画面にしない」、車両ログ
   - 読み込むと、レイヤーはファイルの並びに置き換わる。視点レイヤーは読み込む先の同じレイヤー（自車の画面は役割で、ほかは名前で。既定の名前は日本語・英語のどちらで作ったものでも同じとみなす。
     見つからなければ先頭から順に）を引き継ぎ、向きが動いているもの（メインなど）はキーフレームを残す。Ctrl+Z で元に戻せる
9. 書き出し範囲（I / O キー）、サイズ、コーデックを選んで「書き出す…」。プレビューと同じ合成処理で書き出されるので、見たままの結果になる
   - エンコーダーは、HEVC → H.264 の順に、次の 3 段で使えるものを選ぶ（`engine/exporter.ts` の `pickEncoder`。使ったものはコンソールに出す）:
     ① ハードウェア・動画のフレームレート、② ハードウェア・フレームレートを 30fps と伝える、③ ソフトウェア（遅い）
   - ②: Windows のハードウェアエンコーダー（WebCodecs → Media Foundation）は、1920×1080 より大きいと 30fps までしか登録されていない（RTX 3070 で確認）。
     そのため 50fps の動画を 4K などで書き出すと「エンコーダーが見つかりません」になっていた。フレームレートはビットレートの配分の目安なので、
     30fps と伝え、ビットレートを 30/50 倍にして伝え、実際には 50fps で送る。4K（3840×2160）・HEVC・50fps で 10 秒を 8 秒で書き出せた
   - 仕上がりのビットレートは、指定より 2〜3 割多くなる（1080p で 40Mbps 指定 → 約 51Mbps、4K で約 50Mbps。エンコーダーの癖）
   - この PC で使えるエンコーダーの設定は、自動テストの `encprobe` モードで調べられる（大きさ・コーデック・ハードウェア・ビットレート・フレームレートの組み合わせ）

編集内容は動画と同じフォルダの `<動画名>.insv.motorecomovie.json` に自動保存され、次に開いたときに復元される（前の名前のときの `<動画名>.insv.reframe.json` しか無ければそれを読み、保存は新しい名前へ。古いファイルは消さない）。

## 音声（走行中の音を整える）

右のメニューの「音声」。プレビューと書き出しの音を整える（既定でオン。`core/audiofx.ts`・`engine/audiofx.ts`）。
Insta360 のマイクは、エンジン全開で振幅の上限に張り付き（X6 の 2026-10-11 の 15:04 など）、雨・水しぶき・風切りの「サー」という広い帯域の雑音が乗る
（X5 の 2026-08-13 の雨の日は、エンジンの倍音がほとんど見えないほど）。左右は同じ音（モノラル）。

1. 音割れを補修する: ffmpeg の `adeclip`（張り付いた所を前後の波形から推定して戻す）
2. エンジン音以外を抑える: 4096 点（85ms）の短時間フーリエ変換で、周波数方向の床（±8 ビンの大きさの幾何平均 × 1.11 = 雑音の中央値の目安）より
   2.5 倍以上突き出た所（エンジンの倍音の線）は残し、1.2 倍以下（雑音）は設定の dB だけ下げる。200Hz 以下は下げない（低い回転では倍音の間隔がビンより狭い）。
   ゆらぎ（ミュージカルノイズ）を減らすため、ゲインを時間方向に 3 フレームの最大値 → 3 フレームの平均にする。合成した音で、倍音は −0.4dB、倍音の間の雑音は 12dB の設定で −7.7dB
   （`test/audiofx.test.ts`）。ffmpeg の `afftdn` も試したが、雨の日の X5 ではエンジンの倍音まで消えた
3. 高い音を切る（既定 2000Hz、0 で切らない。1500Hz と聞き比べて決めた）: 2 次のローパスを 2 段（4 次）。巡航で排気音が小さいとき、風切り・ロードノイズの 2〜8kHz の「サー」という音
   （「水が流れているような音」）が目立つ。排気音は 120〜500Hz に集まり、倍音が見えるのは 1.5kHz まで（X6 の 2026-09-19 の 13:49。2〜4kHz の帯の方が 1〜2kHz より強かった）
4. 音圧を抑える: コンプレッサー（しきい値を超えた所を 3:1）→ リミッター（ピーク −1dBFS）

X6 の 15:04 前後の 20 秒: 1 秒ごとの音量 −13〜−1.6dBFS（ピーク 1.06）→ −16〜−9.9dBFS（ピーク 0.55）。映像とのずれ 5ms。
聞き比べ用の音: `testdata/audio/`（元 / 整えた。0919 の 13:39〜（ローパス 1500Hz と 2000Hz）・1011 の 14:55〜）。

「高い音を切る」と「音圧を抑える」は、再生しながらかける（`core/audiofx.ts` の `Dynamics`: 2 次のバターワース 2 段のローパス → RMS 50ms のコンプレッサー
（3:1、アタック 10ms・リリース 250ms、下げた分の 4 割を戻す）→ 5ms 先読みのリミッター（必要なゲインの直近 5ms の最小値を 5ms で平均。ピークを必ず −1dBFS 以下に））。
プレビューではデコードした音にかけ（先読み 0.5 秒なので、設定は 0.5 秒以内に聞こえる）、書き出しでは区間の音に同じ処理をかけて AAC にする（プレビューと同じ音）。
「音割れを補修する」と「エンジン音以外を抑える」だけは重いので、動画を開いた後とその設定を変えた後に裏で作り（23 分の動画で約 2 分: 取り出しと音割れの補修 67 秒、
雑音 20 秒、AAC 31 秒）、アプリのキャッシュ（ユーザーデータの `cache/audio-<動画>-<設定>.m4a`、音割れの補修で 1 を超えないよう 0.5 倍で保存）に置く。
できるまでは動画の音に「高い音を切る」「音圧を抑える」だけをかけて鳴らす。
雑音を抑える処理は 20 秒ずつ（前後に余白を付けて）解析スレッドで行う。区切りはフーリエ変換のずらし幅の倍数にする（つなぎ目で音が変わらない）。

## 車両ログが無いとき

画角の自動切り替え・浮遊標識・水平の補正（傾きを残す）は、車両ログが無くても、動画の IMU（ジャイロと加速度）から推定した値で動く
（`core/imu-telemetry.ts`。開くときに解析スレッドで 0.3〜0.5 秒）。ログがあっても、ログを無効にしたときはこちらを使う。
メーター類・地図・車体挙動の乱れには使わない（推定の車速などを実測のように見せないため、これまでどおり「ログなし」）。

| 値 | 求め方 |
|---|---|
| リーン角 | 前方の軸まわりの回転（ジャイロ）を積分し、まっすぐ走っている所（旋回していない = リーン 0 のはず）でずれを求めて引く |
| 旋回 | 上まわりの回転 ÷ cos(リーン) |
| 車速 | コーナーでは v = g·tan(リーン)·0.86 / 旋回の角速度（バイクは曲がる力と重力の合力の向きに倒れる。タイヤの幅の分、車体は理屈より少し深く倒れるので 0.86 を掛ける）。その間は前後の加速度で積み上げ、止まっている間は 0（前後対称のカルマン平滑化） |
| 前後 G | カメラの加速度の前方成分 × 0.87（カメラの台の揺れの分）から、20 秒のゆっくりした変化（坂）を引く |
| 停止 | 振動込みのジャイロ（2 秒の二乗平均）が 16°/s 以下、かつ細かい揺れ（0.3 秒平均）が 4.5°/s 以下、かつ旋回していない |
| 走った道 | 旋回を積分した方位と、車速で積み上げた位置（GPS が無いので地図とは合わない。標識の置き場所だけに使う） |

走行状態（`core/riding.ts`）は、スロットルの記録が無いので前後 G だけで加速を判定する。コーナーと曲線半径（`core/corners.ts`）はログのときと同じ処理。

  1011 知床 3 本目の「巡航なのに停止」の多くは、ログが記録されていない区間（正解の側が判定できない）
- 車速は、まっすぐな所が長く続くと加速度の積み上げのずれで外れる。浮遊標識の位置（進入地点の 25m 手前など）はその分ずれる

レンダーの自動テスト（`REFRAME_AUTOTEST=render`）の job では、視点をリグ座標の行列（`rigView`）と重力の向き（`rigDown`）で直接指定できる（`printView` で表示）。
切り出した動画で、元の動画と同じ向きの画を描くのに使う。ほかに `rs: false`（ローリングシャッターの補正なし）、`cut: false`（つなぎ目をずらさない）、
`debug: 1/2/3/4`（レンズ0だけ・レンズ1だけ・混ぜる帯・継ぎ目の距離）、`seamQ`（継ぎ目の距離を固定）、`seamIters`（継ぎ目を求め直す回数。シーク直後と同じ 1 回など）がある。
render の引数 `imuLean: true` で車両ログ無しの推定のリーン角、`logOff: true` で「ログを読み込んで無効にした」状態にする。

UI は環境変数 `REFRAME_AUTOTEST` で自動操作できる（`src/renderer/src/autotest.ts`）。例: `ui` モードで開く・シーク・編集・閉じる・書き出し・画面キャプチャを順に実行する。
自動テスト中はユーザーデータを一時フォルダに切り替えるので、普段の履歴は変わらない。また動画の横の編集内容（`.motorecomovie.json`・`.reframe.json`）は読むだけで書き換えない。
`render` モードの `gyroShiftMs` はフレームの時刻からジャイロの時刻への補正をずらす（スタビライズの時刻合わせの確認用）。`body: { source, from, to, offset }` は自車の継ぎ目の型を作って使う（ジョブの `bodyOff: true` で使わない）。`band` モードは帯の画像を書き出す（`ranges: [[開始, 終了, 枚数]…]`）。`ui` モードの `{bodyRange: [開始, 終了]}` は型を作る範囲を限り、`{until: 'body'}` で型ができるまで待つ。
`render` モードは指定した時刻を描いて PNG にする。継ぎ目の確認には、ジョブの `debug: 4`（継ぎ目の帯と距離の色）、`groundDump: true`（ビンごとの地面の距離・模様・一致度）、
`probeBins: [ビン…]`（そのビンの全候補の不一致）、`pixelBins: [[x, y]…]`（出力の画素が継ぎ目のどのビン・継ぎ目から何度に当たるか）を使う。

## 表示の言語（日本語・英語）

- ツールバーの右端で 日本語 / English を切り替える。選んだ言語はこのパソコンに覚えておく（初回は OS の言語）。メインメニュー（ファイル・編集・表示・ウィンドウ）も同じ言語になる
- 動画に描き込まれる文字（車体挙動の乱れの表示と指標の名前、「車両ログなし」、数値一覧の項目名、地図・標高・方位帯のデータなしの表示）は、書き出しの欄の「動画に入る文字」で選ぶ（画面と同じ / 日本語 / English）。画面は日本語のまま英語の動画を作れる
- レイヤーの名前: 既定の名前（メイン・後ろ・サイバー風メーター・視点 2 など）は、日本語・英語のどちらで作ったものでも今の言語で表示する。自分で付けた名前はそのまま
- 仕組み: ソースには日本語のまま書き、`t('日本語')`（画面の言語）／`tr(言語, '日本語')`（動画の文字）で包む。英語は `src/renderer/src/i18n/en-*.ts` の辞書（日本語 → 英語）。差し込みは `t('{n} 件', { n })`。名前の表（ウィジェット・ショット・乱れの指標など）は日本語のまま持ち、表示するところで訳す（表の行には `// i18n-ignore`）
- `test/i18n.test.ts` で、辞書の漏れ・差し込みの名前の食い違い・英語に残った日本語・t() で包み忘れた画面の文字列を確かめる

## 書き出しの速さ

- 1920×1080・HEVC で 10 秒（500 フレーム）を約 6 秒（実時間の約 1.7 倍）。内訳は 1 フレームあたり デコード 約 3.5ms・描画 約 3ms（動的なつなぎ合わせ 約 1.3ms を含む）
- 書き出しの最後に「書き出しの内訳」とデコーダーの集計（キーフレームからやり直した回数・その理由・使わずに捨てたフレーム数）をログに出す
- 以前は、ときどき書き出しが極端に遅くなっていた（1 フレーム 235ms）。原因はデコーダーが「出力された位置より 2 枚以上前」のフレームを早めに捨てていたこと: ハードウェアデコーダーは何枚かまとめて出力することがあり、使う側が少し遅れると（開いた直後の最初の書き出しのシェーダーの準備など）これから使うフレームまで捨ててしまい、キーフレームからのやり直しが連鎖していた。いまは「求められている位置より前」だけを捨てる（`engine/decoder.ts`）

## 既知の制限

- 対応は X6（キャリブレーション V6、IMU 軸の対応は X6 で実測）。他の機種では軸や時刻の補正が合わない可能性がある
- 出力は透視投影のみ（リトルプラネットなどの投影は未対応）
- MotoReco のログは "TO Custom v1" 形式の CSV と、R1200GS（K51）の .dat・BMW.ddf で確認した。.dat のデコードは MotoRecoViewer のソースの移植で、同じ .dat を MotoRecoViewer で変換した CSV と全列・全行が一致する

## 削除した機能

- 走行地点の解説（Wikipedia・地質図から集めた字幕）は、別のツールで入れることになったので外した（2026-10-19）。古いプロジェクトに残っている解説と「走行地点の解説（字幕）」のレイヤーは、開いたときに読み捨てる
